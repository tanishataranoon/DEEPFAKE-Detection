# DEEPFAKE Detection

A deepfake video detection research project using a **multi-branch architecture** that analyzes both the visual appearance of faces and their temporal behavior across video frames.

> **Project Status: 🚧 ONGOING**

---

## 📌 Project Overview

The goal of this project is to develop a deepfake detection system capable of distinguishing between **real** and **manipulated (fake)** videos while also estimating **uncertainty** in its predictions.

The proposed system consists of two main branches:

* **Appearance Branch** — analyzes spatial/visual characteristics of individual face crops.
* **Temporal Branch** — analyzes changes and inconsistencies across sequences of video frames.

The evidence generated by the branches is intended to be combined using **Dempster-Shafer evidence theory** to produce the final prediction.

The final system is designed to provide **three outputs**:

1. **Real**
2. **Fake**
3. **Uncertainty**

# 🔄 Preprocessing Pipeline

The preprocessing stage converts the original videos into structured face-level information that can be used by both branches.

### 1. Video Reading and Frame Extraction

Videos are read using OpenCV and individual frames are extracted.

### 2. Face Detection

**YOLO Face Detector** is used to locate faces in each frame.

### 3. Quality Filtering

Low-quality face detections are filtered using criteria such as:

* Minimum face size
* Blur/quality threshold

Current configuration includes:

```text
Minimum face size : 19 pixels
Blur threshold     : 16
```

### 4. Face Tracking

**ByteTrack** is used to track detected faces across consecutive frames.

This helps maintain the identity of the same face throughout a video sequence.

### 5. Face Cropping

Detected faces are cropped and resized to:

```text
224 × 224 pixels
```

These face crops are used as the basic input for the Appearance Branch and as sequential inputs for the Temporal Branch.

---

# 🧾 Metadata

Instead of creating and storing completely separate video files for every training sample, the preprocessing pipeline creates a **metadata CSV** describing the samples.

The metadata stores the information required to reconstruct the required clips, including information such as:

* Source video
* Frame IDs
* Face bounding boxes
* Labels
* Clip information

The dataset loader uses this metadata together with the original videos to reconstruct training samples.

The preprocessing pipeline previously generated approximately:

```text
Total metadata clips: 188,250
```

This metadata-based approach reduces unnecessary duplication of video data, although reconstructing clips during training introduces additional I/O and processing overhead.

---

# 🎞️ Temporal Clips

The current temporal samples use:

```text
Clip length   : 16 frames
Face size     : 224 × 224
```

A clip is reconstructed from the original video using the frame IDs and face bounding boxes stored in the metadata.

This allows the same preprocessing output to support both:

* Single-frame appearance analysis
* Multi-frame temporal analysis

# 🔀 Dataset and Leakage-Free Splitting

The project uses a **group-level dataset splitting strategy**.

This is important because multiple manipulated videos may originate from the same original/source video.

All videos belonging to the same source group are kept inside the same dataset split.

Therefore:

```text
Source Group
     │
     ├── Real Video
     ├── Fake Version 1
     ├── Fake Version 2
     └── Fake Version 3
             │
             ▼
       Same Dataset Split
```

This prevents source-video leakage between training, validation, and testing.

# 👁️ Appearance Branch

The Appearance Branch focuses on the **spatial/visual evidence** contained in individual face crops.

Current architecture:

```text
224 × 224 Face Crop
        │
        ▼
      AIMv2
        │
        ▼
Feature Representation
        │
        ▼
   Evidence Head
        │
        ▼
      EDL
(Evidential Deep Learning)
        │
        ▼
Dempster-Shafer Evidence
        │
        ▼
 ┌───────────────┐
 │ Real Evidence │
 │ Fake Evidence │
 │ Uncertainty   │
 └───────────────┘
```

The Appearance Branch does not simply produce a conventional binary classification.

It produces **evidence for the classes together with uncertainty**.

---

# 🧠 Evidential Deep Learning (EDL)

The project uses **Evidential Deep Learning (EDL)** to represent the model's confidence as evidence rather than forcing every prediction to be completely confident.

The EDL stage allows the model to distinguish between:

```text
Strong evidence for Real
Strong evidence for Fake
or
Insufficient / conflicting evidence → Uncertainty
```

This is particularly useful for deepfake detection because some videos may contain ambiguous or low-quality evidence.

---

# 🔬 Dempster-Shafer Evidence Theory

The project incorporates **Dempster-Shafer evidence theory** to represent and combine evidence.

The evidence can be interpreted as support for:

```text
Real
Fake
Uncertainty
```

The two branches can independently generate evidence, which can later be combined through an evidence-fusion process.

Conceptually:

```text
Appearance Evidence
        │
        ├── Real
        ├── Fake
        └── Uncertainty
                │
                ▼
        Evidence Fusion
                ▲
                │
        ┌───────┴───────┐
        │               │
Temporal Evidence       │
        │               │
        ├── Real        │
        ├── Fake        │
        └── Uncertainty │
```

The final system is intended to use this evidence rather than relying only on a single conventional softmax prediction.

# 🎬 Temporal Branch

The **Temporal Branch is currently ongoing**.

The purpose of this branch is to detect information that cannot be reliably identified from a single frame.

It will analyze sequences of face crops to capture:

* Facial motion
* Frame-to-frame inconsistencies
* Temporal artifacts
* Abnormal motion patterns
* Changes in facial appearance
* Inconsistencies introduced during manipulation

The existing preprocessing pipeline already provides the frame-level information required to construct temporal clips.

# ⚠️ Current Computational Bottleneck

The major current limitation is **training speed**.

The dataset loader reconstructs 16-frame clips from the original videos using metadata.

This means training involves:

```text
Metadata
   ↓
Find Original Video
   ↓
Read Required Frames
   ↓
Apply Bounding Boxes
   ↓
Create Face Crop
   ↓
Construct 16-Frame Clip
   ↓
Send to Model
```

This can result in significant disk I/O and CPU overhead during training.

Because the available computational resources are limited, full-scale training is currently time-consuming.
